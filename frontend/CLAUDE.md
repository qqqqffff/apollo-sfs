# Frontend

React 18.3 + TypeScript single-page application built with Vite 7. Served in production by an nginx container inside the Docker Swarm stack (manager node, standard tier).

## Stack

| Concern | Library |
|---------|---------|
| UI framework | React 18.3 + TypeScript |
| Build tool | Vite 7.3 |
| Routing | TanStack Router 1.93 (file-based) |
| Data fetching | TanStack Query 5.62 |
| Styling | Tailwind CSS 4.2 |
| Icons | react-icons 5.6 |
| Bot protection | Cloudflare Turnstile (`@marsidev/react-turnstile`) |
| HTML sanitization | DOMPurify 3.4 |
| DOCX preview | mammoth 1.12 |
| Unit tests | Jest 29 + `@testing-library/react` |
| E2E tests | Playwright 1.60 |

## Development

```bash
cd frontend
npm ci
npm run dev        # Vite dev server on :5173 with /api proxy to :8080
```

Vite's `vite.config.ts` proxies `/api/*` requests to the Go API at `http://localhost:8080` so you can run the frontend independently without modifying any URLs.

## Building for Production

```bash
npm run build      # tsc -b && vite build → dist/
```

The Dockerfile performs the same steps in a Node build stage, then copies `dist/` into an nginx Alpine image that serves on port 3000. The nginx config inside the container (`nginx.conf`) handles SPA fallback (`try_files $uri /index.html`).

## Routing

TanStack Router uses file-based routing. Adding a new page:

1. Create `src/routes/my-page.tsx` exporting a `Route` created with `createFileRoute('/my-page')`.
2. Run `npm run build` or the dev server — `routeTree.gen.ts` is regenerated automatically.
3. Never edit `routeTree.gen.ts` by hand.

Protected routes live under the `_auth` layout (`_auth.tsx`). Premium-only routes live under `_auth.premium.tsx`. Both redirect unauthenticated users to the login page.

## Authentication

`src/auth.tsx` wraps the app with a Keycloak OIDC provider. On load, it silently checks for an existing session and redirects to Keycloak's hosted login page if needed. The access token is attached to every API request by the TanStack Query client wrapper in `src/api/`.

## Data Fetching Pattern

Use TanStack Query throughout:

```ts
const { data, isLoading } = useQuery({
  queryKey: ['files', folderId],
  queryFn: () => api.listFiles(folderId),
})
```

Mutations that modify server state should call `queryClient.invalidateQueries` with the relevant key so stale data is re-fetched.

## Testing

```bash
# Unit tests
npm test

# E2E (requires running API + DB)
npm run test:e2e

# Via Docker sidecar
docker compose run frontend-tests
```

Playwright tests are in `src/__tests__/` or a top-level `e2e/` directory. Jest tests co-locate with their source files or live in `__tests__/` folders.

## Key Environment Variables

Vite exposes only variables prefixed with `VITE_` to the browser bundle. Everything else is build-time only.

| Variable | Purpose |
|----------|---------|
| `VITE_KEYCLOAK_URL` | Keycloak public URL (e.g. `https://auth.apollo-sfs.com`) |
| `VITE_KEYCLOAK_REALM` | Realm name |
| `VITE_KEYCLOAK_CLIENT_ID` | Public client ID (`apollo-sfs-web`) |
| `VITE_TURNSTILE_SITE_KEY` | Cloudflare Turnstile public site key |
| `VITE_API_BASE_URL` | Base path for API requests (usually `/api/v1`) |

## Production Container

The `Dockerfile` produces a multi-stage image:

1. **Build stage:** `node:lts-alpine` — installs deps, runs `tsc -b && vite build`
2. **Serve stage:** `nginx:alpine` — copies `dist/` and `nginx.conf`

The container listens on port 3000. The Swarm stack places it on the manager node with a `tier=standard` constraint.
